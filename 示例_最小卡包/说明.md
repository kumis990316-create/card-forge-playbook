# 示例_最小卡包 · 说明

这是**能跑通的最小样板**，用来给新卡当骨架。它故意做得极小：一张卡 ＋ 一本世界书（5 条），内容全是教学占位。

## 里面有什么

```
示例_最小卡包/
  01_卡片/
    米拉_卡片.json       卡本体（v2 外壳 ＋ v1 平铺）
    米拉_世界书.json     5 条：2 常驻（C0.x）＋ 3 触发（C1.x/C2.x/C3.x）
  02_源码/
    底图.png             示例底图（512×768，正式做卡换成你自己画的）
  03_成品/
    米拉.png             跑 build_card.js 出的成品（卡片本体在 PNG 的文本块里，前台上传用）
    米拉_导入用.json     跑 export_json.js 从上面那张 PNG 里解出来的（后台导入用）
```

**它是双端写法**：条目的 `position` 顶层与 `extensions` 写了同一个值（顶层 0–4 这一段两端不撞车）。
所以三种输出端口径下都应当是 `0 必须修`（见 `05_输出端与平台.md`）。

| 条目 | 类型 | 演示什么 |
|---|---|---|
| `C0.0 总则（常驻）` | 常驻 | 每轮都要遵守的硬口径怎么写 |
| `C0.1 世界观（常驻）` | 常驻 | 数字口径（`## 三条设定` 恰好三行） |
| `C1.1 米拉（角色条）` | 触发 | 角色条的六小节模板（一句话／标签／外形／怎么上手／台词样本／开门之后） |
| `C2.1 灰渡酒馆（场景条）` | 触发 | 场景条写「场里有什么」＋「会发生什么」 |
| `C3.1 事件：汛期漂来的箱子（触发条）` | 触发 | 事件条怎么给玩家留抓手 |

## 怎么用它

1. 整个目录复制一份，改名成你的卡包名。
2. 改 `01_卡片/` 里的两个 JSON：**先改内容，再改名字与版本号**。
3. 每改一轮跑一次（`--输出端=` 填你那张卡要跑的地方）：

```bash
node 工具/check_all.js 示例_最小卡包 --输出端=双端
```

期望读数：`=== 结论：0 必须修 ===`（示例是双端写法，`酒馆`／`叙梦`／`双端` 三种口径都过）。

4. 出成品（两个形态都从 `01_卡片/` 重出）：

```bash
node 工具/build_card.js 示例_最小卡包 --placeholder    # 没底图时先出占位图
node 工具/build_card.js 示例_最小卡包                  # 用 02_源码/底图.png，出 03_成品/米拉.png
node 工具/export_json.js 示例_最小卡包                 # 再出 03_成品/米拉_导入用.json（后台导入用）
```

**交出去的那份 JSON 一定要是 `export_json.js` 出的**，不是 `01_卡片/` 里的源件：源件的世界书是空壳，导入进去是一张有开场、没规则的空卡。

## 别做的事

- **不要手改 `03_成品/`**：那是生成物，改了下次出图就没了。
- **不要把示例卡当模板发出去**：它只是骨架，内容没有意义。
- **不要在这里直接写你的卡**：复制出去再写，保持示例永远是干净的基线（它是检查器的验收靶子）。
