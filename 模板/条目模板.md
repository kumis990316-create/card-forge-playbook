# 条目模板（复制到 `01_卡片/<名>_世界书.json` 的 `content` 里改）

一个小节只讲一件事；标题里的数量词要和下面的行数一致（改内容就改标题）。

## 一、总则条（`constant: true`，`key: []`）

每轮都进上下文，所以**短、硬、可执行**。只放「每轮都必须成立」的规则。

```markdown
## 这是什么
<这一场是什么，一行>

## 铁则
- <写作用第几人称、称呼怎么定>
- <每轮结尾要给玩家留什么>
- <冲突时以谁为准>
```

## 二、角色条（触发，`## 一句话` 打头）

```markdown
## 一句话
<名字，年龄，身份，一行说清>

## 标签
- <三到五个词，用「·」分隔>

## 外形
- <能拍成画面的具体细节，两到四条；不要写「很美」这种不可复现的形容>

## 怎么上手
- <玩家跟她互动时的第一反应与规矩，两到三条>

## 台词样本
- 「<两句，示范说话风格而不是剧情>」

## 开门之后
- **结局一 · <名字>**：<一句话>
- **结局二 · <名字>**：<一句话>
```

> 六个小节是**检查器要求的最小集**（`check_entries.js` 认 `## 一句话` 就是角色条）。少一节就判必须修。

## 三、场景条（触发）

```markdown
## 一句话
<这是什么地方，一行>

## 场里有什么
- <三到五条具体物件／气味／声音，能拍成画面的>

## 会发生什么
- <在这里会发生的事，给玩家可操作的抓手>
```

## 四、事件条（触发）

```markdown
## 一句话
<什么时候、发生了什么，一行>

## 场里有什么
- <关键物件或线索，两到三条>

## 会发生什么
- <推进方式：玩家能做什么、会有什么后果>
```

## 五、写法要点

- **具体优于形容**：「袖口写满炭笔记号」胜过「看起来很干练」。
- **给抓手**：每条都要留一个玩家能回应、能利用、能破坏的东西。
- **一处一说**：同一个设定不要在两个条目里各写一遍（检查器会报重复句）。
- **触发词是玩家的话**：`key` 写口语说法，不要写设定术语。
